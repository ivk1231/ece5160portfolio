Step Response Data Collection & KF Parameter Estimation
Three step response runs were conducted at PWM=120 (~47% of max) driving the robot toward a wall. Run 1 was unusable — the robot started ~4m away, placing it at the ToF sensor's long-mode saturation limit (~3975mm), so the sensor returned a clipped constant value for the entire acceleration phase and logged 0 valid points. Run 2 (start ~2.7m) and Run 3 (start ~3.5m) both produced usable data, with Run 3 being the cleaner of the two. A key data processing issue was identified: the Arduino loop runs at ~100Hz but the ToF sensor only updates at ~27Hz, meaning ~75% of logged rows were duplicate distance values. Feeding these duplicates into np.gradient created large artificial speed spikes from near-zero time denominators. The fix was to deduplicate — computing speed only between rows where distance actually changed — then applying a 5-point median filter and clipping values beyond 3×IQR from the median. From Run 3, steady-state speed was measured as ~2500 mm/s and 90% rise time as ~1.25s, yielding drag d = 0.000186 and momentum m = 0.000103, averaged with Run 2 to give final values d = 0.000200, m = 0.000101.
Kalman Filter Tuning
The KF was initialised with a 2D state vector [position, velocity], discretised at ΔT = 34ms matching the ToF update period, with C = [[-1, 0]] since only position is directly measured. Initial tuning with σ₁=25, σ₂=10, σ₃=30 produced good distance tracking but a terminal velocity of ~5000 mm/s — roughly 2× the physically measured value. Reducing σ₂ to 5 brought this down to ~4100 mm/s but the velocity was still too high, revealing the root cause: the control input u was being normalised as PWM/STEP_PWM (giving u=1.0 at full step) rather than PWM/255.0 (the absolute normalisation used when estimating d and m from the step response). Since B was derived assuming u = PWM/255, feeding u = PWM/STEP_PWM = 120/120 = 1.0 instead of u = 120/255 = 0.471 effectively doubled the modelled thrust, pushing terminal velocity to u/d = 1.0/0.000200 ≈ 5000 instead of the correct 0.471/0.000200 ≈ 2350 mm/s. Correcting the normalisation to u = PWM/255.0 with final parameters σ₁=25, σ₂=5, σ₃=30 produced a KF that tracks distance cleanly through noisy regions and converges to ~1950 mm/s — consistent with the measured steady-state speed and physically reasonable given the step response runs did not fully plateau before wall impact.
